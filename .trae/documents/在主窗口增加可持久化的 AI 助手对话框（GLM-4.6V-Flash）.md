## 设计选择
- 采用非模态窗口更合适：不阻塞主流程，用户可边操作软件边问问题；同时满足可拖动/最小化/关闭。
- 实现形式优先选非模态 QDialog（带窗口按钮）；如果你更想“停靠在主窗口边缘/可浮动”，可改为 QDockWidget。

## UI 改动
- 在主窗口顶部工具栏最右侧新增“AI 助手”入口（图标或“AI”按钮）。
- 点击后显示 AI 对话框；再次点击若已打开则置顶激活。

## 对话框交互
- 消息区：支持滚动显示（用户/助手分气泡或简单分段）。
- 输入区：多行输入 + 发送按钮；回车发送、Shift+Enter 换行。
- 附件区：支持“添加附件”选择 图片/Excel/PDF；展示已选附件列表，可移除。
- 会话控制：清空会话、导出会话（可选）。

## 历史记录持久化
- 关闭窗口不销毁实例：改为 hide()，下次 show() 直接回到原会话。
- 同时把会话落盘（JSON）：软件退出/窗口关闭时保存；启动/打开时恢复。
- 存储位置使用用户目录（如 AppData/本地目录），避免跟随打包文件夹变化。

## 知识来源与“保密”约束
- 主要基于 使用说明书.md 做检索式引用（从说明书按标题切分成 sections，按关键字/相似度选 TopK 段落作为上下文）。
- 系统提示词中明确：只回答“如何使用本软件”，拒绝透露源码/算法/实现细节；不输出任何代码片段、不提函数名/文件路径。
- 若用户追问实现原理：统一引导到“用户可见的操作步骤/菜单位置/导入导出规则”。

## 模型调用（GLM-4.6V-Flash）
- 使用官方 v4 Chat Completions 端点：https://open.bigmodel.cn/api/paas/v4/chat/completions（Bearer 方式鉴权）。
- API Key 不硬编码：运行时从指定文本文件读取；并提供 UI 设置入口（可选）以便部署时每个单位自行配置。
- 请求放到后台线程执行（QThread/worker），避免卡界面；提供“正在思考/取消请求”。

## 多模态输入策略（兼顾“可上传”与“无需公网 URL”）
- 图片：读取本地文件转 base64，按文档支持的 data:image/*;base64 方式传入 image_url。
- Excel：本地解析（pandas/openpyxl），抽取表头+前 N 行+基础统计/列名说明，作为 text 输入给模型（更隐私，也不依赖公网 URL）。
- PDF：新增轻量依赖 pypdf（纯 Python），抽取前 N 页文本并做长度截断后作为 text 输入；若解析失败提示用户换为导出文本/截图。
- 说明：虽然文档支持 file_url，但它需要可被模型服务器访问的 URL；桌面端本地文件默认没法直接给 URL，因此采用“本地解析→文本喂给模型”的方式最稳、也最符合“只做软件使用帮助”。

## 安全与稳定性
- 不在日志/弹窗中显示 API Key；错误信息脱敏。
- 限制单次输入与附件解析后的最大字符数，防止超长卡顿。
- 失败重试与超时控制（避免无响应）。
